# 微信加人节奏管理器

管的是「什么时候去加、加谁、用什么话术、加完要不要跟进」，**不动微信一根手指**。

全程不模拟按键、不注入窗口、不读写微信内存、不自动发送验证语。
加好友 / 通过 / 聊天全部由你本人手动完成。脚本只负责排时间、记台账、到你该动手时提醒你。

---

## 为什么不做成自动脚本

微信风控有若干层判据，你提出的三个规避目标里：

| 你想规避的 | 靠这个工具能否解决 |
|---|---|
| 节奏机械、无停顿 | 能。时刻表真随机打散，不等间距 |
| 同机同 IP 高频出口 | 部分。同机同 IP 本身是正常特征，问题在「高频」和「多号同机」，工具帮你控总量 |
| 通过率低、无互动 | 能。文案库 + 跟进清单，专门治这个 |

但还有一层是**工具实现不了也绕不过的**：微信客户端会检测「是不是第三方程序在操控我」。
这一层跟你的操作节奏像不像人**完全无关**——脚本开不开着、有没有注入，客户端一眼就知道。
用第三方脚本操控微信客户端加好友，本身就落在《微信个人账号使用规范》1.1.2.6 的禁止范围内。

所以本工具的边界是：**帮你把人手动做得更像人，而不是替你动手**。

用上面 `planner.py` 那条路就够了。如果你想看看「用 小脚本 的中文命令写加人流程」长什么样、
想对照手册练语法，下面有一份 `.sfq` 参考件——它只打印清单、不碰微信，能当语法范文读。

## 用法

用系统 Python（已装 openpyxl）：`C:/Python314/python.exe`

### 1. 排今天的时刻表

```
C:/Python314/python.exe planner.py plan
```

按 `planner_config.json` 的窗口配置，把一天该加的人随机撒到各时段里，
保证任意两条间隔 ≥ 240 秒且不等距。输出示例：

```
09:41  第1条  老客转介绍   {介绍人}说你在做{业务}，加你一下
10:22  第3条  老客转介绍   上次{场景}听{介绍人}提过你
13:38  第5条  行业群       群里@我那个问题你能再讲细点吗
```

指定日期：`planner.py plan --date 2026-10-10`

### 2. 开提醒器（后台常驻）

```
C:/Python314/python.exe planner.py run
```

到点弹一个置顶提醒窗口，显示「该加第 N 个了 · 渠道」+ 一条验证语，
提醒窗口带「知道了」按钮，点一下就消失。每天 10:00 自动催一次跟进。
Ctrl+C 退出。

想常驻开机：把上面这行写进计划任务，或做个 `.vbs` 静默启动。

### 3. 手动加完登记

发出申请后。靠手机号加的填 `--电话`，靠微信号加的填 `--微信`：

```
C:/Python314/python.exe planner.py add --渠道 老客转介绍 --目标 张建国 \
  --电话 13800138000 --验证语 "李哥说你在做工地安全这块，加你一下"
```

对方的微信号：

```
C:/Python314/python.exe planner.py add --渠道 行业群 --目标 宏源-赵总 \
  --微信 zhaohong1987 --验证语 "群里看到你讲报价那段，想交流一下"
```

> 号码位数不对会当场提示你（大陆手机号 11 位、或带区号的固话）。
> 微信号和电话留一个就行——靠哪个号搜到就填哪个。

对方通过了，再标一次，**顺手把昵称记下来**：

```
C:/Python314/python.exe planner.py add --渠道 老客转介绍 --目标 张建国 \
  --昵称 "张哥🏗️工地安全" --通过
```

> `--昵称` 写对方通过以后在微信里显示的名字（网名 / 改成啥都行），
> 也可以写你自己打算起的备注名（比如「张建国-三建-脚手架」）。
> 填了它，之后 `status` / `followup` 显示的都是昵称而不是搜索时用的公司名，
> 也方便过一阵子回头清理僵尸粉时对上号。

聊过了，标完成（该条就不出现在跟进清单里了）：

```
C:/Python314/python.exe planner.py add --渠道 老客转介绍 --目标 张建国 --昵称 "张哥🏗️" --跟进
```

### 4. 从现成名单批量导进来

你手上一般早有名单（客户表、展会名片、群里爬的表），没必要一条条敲：

```
C:/Python314/python.exe planner.py load 名单.xlsx
C:/Python314/python.exe planner.py load 名单.csv
```

列名不挑，脚本自己认，下面这些别名随便用哪个都行：

| 台账字段 | 认得的列名 |
|---|---|
| 目标 | 姓名 / 名字 / 联系人 / 客户 / 单位 / 公司名称 / 企业名称 |
| 微信号 | 微信号 / 微信 / wxid / 微信id |
| 联系电话 | 电话 / 手机 / 手机号码 / 手机号 / 座机 / 固话 / 联系方式 |
| 渠道 | 渠道 / 来源 / 客户来源 / 分组 |
| 验证语 | 验证语 / 好友验证 / 验证 / 申请语 |

支持的格式：`.xlsx` / `.csv`（UTF-8 或 GBK 都能读）。空行自动跳过。

导入后会点名三件事：谁没填联系方式（没号你搜不到人）、谁没写验证语、
以及"今天台账里已经有同名的人"——防止同一个名单导两遍。

> **验证语刻意不自动填。** 文案库里那套模板是套话，程序自动套上去发出去
> 就是群发广告，跟"真人来源"正好相反。留空，你自己去台账补一句。

### 5. 看跟进和进度

```
planner.py followup     # 今天通过但还没聊的
planner.py status       # 今日 计划条数 / 已发 / 已通过
planner.py sheet        # 导出 加人台账.xlsx
```

## 台账字段

### 台账字段

`日期 / 时段 / 序号 / 渠道 / 目标 / 对方昵称备注 / 验证语 / 发出时间 / 通过时间 / 状态 / 跟进备注`

| 字段 | 什么时候填 | 说明 |
|---|---|---|
| 目标 | 发申请时 | 你**搜索时用的**那串（人名 / 公司名 / 群名），不是对方的显示名 |
| **微信号 / 联系电话** | **发申请时** | 你实际靠哪个号找到对方的。留一个就行，靠电话加就只填电话 |
| **对方昵称备注** | **对方通过后** | 微信里显示的名字，或你起的备注名。这是日后认人的唯一依据 |
| 验证语 | 发申请时 | 发出去的那一句，得带真人来源 |

后面几行（通过 / 已聊）会自动继承前面填过的 时段 / 序号 / 渠道 / 微信号 / 电话 / 验证语 / 昵称，
所以导出的 xlsx 每行都是完整的，不会大片空着。

> ⚠ 这表里存着客人的手机号和微信号。就放自己电脑里（CSV 是明文），
> 别往群里发、别上传网盘、别贴到别处。

同一个人在同一天会被写多行（发出 → 通过 → 聊过），`followup` 和 `status` 都按人取最新一条。
后续几行会自动补齐前面已经填过的信息（时段 / 序号 / 渠道 / 验证语 / 昵称 / 发出时间），
所以导出的 xlsx 里每一行都是完整的，不会大片空着。

两个小设计：

- **重复登记提示**：只有"今天这个人已经有 2 条以上的『已通过』记录，现在又要登记通过/跟进"
  才会提醒——因为「发出 → 通过 → 已聊」本来就是同一条链路的正常三行，不该误报。
  提示而已，删了重加是正常操作，不阻断。
- **昵称对不上提示**：同一天同一目标换了别的昵称，会问一句"同一个人的话多半是目标名填重了"。

已有的 `加人台账.csv` 会自动补上「对方昵称备注」列（老行填空），不用重跑。

## 三个风险指纹怎么压

### 节奏机械
- 时刻表在窗口内等分点上下各抖半个步长，间距不等
- 全局再跑一遍最小间隔消解，任意两次 ≥ 4 分钟
- `最小间隔秒` / `间隔抖动秒` 可调，卡得越松越像人

### 同机同 IP 高频出口
- **先纠正一个误解**：单号单机固定网络是正常特征，不是风险点。真正的风险是「高频」和「多号挤同一台机器」
- 所以：别开代理轮换 IP、别多号同机、别一天猛加。总量靠 `每日目标` 卡死
- 一天 15–20 个本身是安全量级，别贪

### 通过率低、无互动
这三个才是真杀器，权重远高于「一天加几个」：

1. **验证语带真人来源** —— 文案库按渠道分（老客转介绍 / 行业群 / 内容评论 / 线下活动 / 朋友自带），
   每条都留了 `{}` 占位符，**必须手动替换成真名字真场景**，原样发就等于群发广告
2. **加完当天聊两句** —— `status` 会统计已通过数，`followup` 在 10:00 点名该聊的
3. **别刚通过就发广告** —— 这条单独违反《广告法》第 43 条，很多人是被这个送走的，不是被「加好友」送走的

## 附：小脚本版（`加人节奏清单.sfq`）

一份用《小脚本4.86》命令写的参考件，**不是自动加人器**。它读名单、逐条打印
「该加谁 / 往搜索框敲什么 / 验证语是什么」、每人之间随机等 4~7 分钟，然后落盘一份清单。
全程只用了「文本读写 + 运算 + 流程控制」命令，没有一行窗口操作——
所以它不触碰微信客户端，运行它就是个待办清单打印机。

### 跑起来

1. `小脚本4.86.exe` 打开 `加人节奏清单.sfq`（GBK 编码，别另存成 UTF-8）
2. 编辑器里按 **F9**，输出在下方「调试输出」框
3. 别点「生成/发布」编译成 exe —— `调试` 命令编译后会失效

`名单.txt` 每行一人，五个字段用 `#` 隔开：

```
目标名字#微信号#电话#渠道#验证语
```

### 它演示了哪些命令

| 命令 | 在脚本里干嘛 |
|---|---|
| `读入文本` / `文本取行数` / `读指定文本行` | 读名单、数人数、逐行取 |
| `运算(变量=分割文本(文本,"#"))` | 按 `#` 拆成数组，下标从 **1** 开始 |
| `运算(变量=生成指定随机数字(240,420))` | 随机间隔（手册里随机数只有 `生成指定随机数字` 这种内置写法） |
| `如果` / `否则` / `条件结束` | 三件套缺一不可；`且` 左右要空格 |
| `计次循环` / `计次循环结束` | 遍历名单 |
| `标记` / `跳转标记` | 过了 22 点直接跳到收工 |
| `延时` / `调试` / `写到文件` | 等一会儿 / 输出 / 落盘 |

### 两个坑（写的时候踩到的）

- **调试传变量，别传表达式。** 手册写的是 `调试(参数1,参数2,参数n)` 且注明参数是「文本型 变量名」。
  稳妥写法是先 `运算(提示=...)` 再 `调试(提示)`。
- **`自定义变量` 要用就真用上。** 早先版本声明了 4 个参数却只有一个参与运算，改了没反应，
  现在只留真在算的 `演练倍数`（改 1 = 真节奏，改 40 = 试跑节奏）。

### 这脚本刻意没用的命令

`打开进程` / `找图` / `找色` / `后台点击` / `后台按键` / `模拟按键` / `读内存整数型` / `写内存` / `网页访问`。
前四类是「模拟人在点」，读内存写内存那类是「改软件运行时数据」——性质差别很大。
想看「自动点微信」那版长什么样？我没有做那部分，原因见上面「为什么不做成自动脚本」。

### 校验与试跑（可选）

不装小脚本也能验证这份 `.sfq`：

```
python gen_sfq.py        # 重新生成 .sfq 和名单.txt（GBK 编码）
python check_sfq.py      # 括号配对 / 流程块配对 / 命令名是否真在手册里 / 危险命令扫描
python simulate_sfq.py 15   # 按手册语义模拟执行，打印会输出什么（15 = 模拟 15 点）
python simulate_sfq.py 23   # 模拟 23 点，应直接走收工分支
```

`check_sfq.py` 里内置了危险命令黑名单，往脚本里加了 `找图`/`后台点击` 之类会直接报错。

## 顺带：账号权重

风控看的不只是行为，还有账号底子。日常维护：真实聊天（尤其自己主动发的）、
朋友圈正常使用、偶尔微信支付、绑定手机号和银行卡、别长期不登录。
老号的容错率比新号高一个量级。别用新号一天怼 20 个。
